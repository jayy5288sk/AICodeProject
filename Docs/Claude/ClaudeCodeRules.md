# Claude Code 행동 규칙
> Claude Code가 이 프로젝트에서 반드시 따라야하는 규칙

---

## 행동 원칙

### 1. 사고 우선 (Think Before Coding)
> 가정을 숨기지 말고, 모호하면 멈춘다. 
- 가정을 명시적으로 말한다. 불확실하면 질문한다.
- 해석이 여러 갈래라면 모두 제시하고 임의로 고르지 않는다.
- 더 단순한 방법이 보이면 사용자에게 알린다.
- 코드를 읽기만 하고 새로운 결론은 "미검증"인 상태로 표기한다.


### 2. 단순함 우선 (Simplicity First)
> 문제를 푸는 최소한의 코드만 작성하라.
- 요청 범위 밖의 기능을 추가하지 않는다.
- 한 번만 쓰는 코드에 추상화를 도입하지 않는다.
- 요청하지 않은 "확장성"이나, "가능성"을 미리 만들지 않는다.
- 일어날 수 없는 상황을 위한 예외 처리를 작성하지 않는다.

### 3. 외과적 변경 (Surgical Change)
> 필요한 곳만 건드린다. 
- 인접 코드, 주석, 포맷팅을 임의로 "개선"하지 않는다.
- 구동에 문제가 없는 코드를 리팩토링 하지 않는다. 
- 본인 변경 때문에 쓰이지 않게 된 변수, 함수는 정리한다. 원래 있던 죽은 코드는 보고만 한다. 
- **판단 기준** : 변경을 가하는 모든 행위는 사용자의 결정에서 직접 나와야 한다.

### 4. 검증 가능한 목표 (Goal-Driven Execusion)
> 성공 기준을 먼저 정하고 확인될 때까지 진행한다.
- 여러 단게로 작업을 나눠야 할 경우를 포함한 모든 상황에서 작업 계획을 브리핑한다. 
- 예시는 다음과 같다. 
```
1. [단계 명] → 확인: [확인 항목], [확인 항목]
2. [단계 명] → 확인: [확인 항목], [확인 항목]
```
---

## 작업 범위 규칙
- 요청 혹은 승인받은 파일과 기능 외의 코드는 수정하지 않는다.
- 다른 파일에서 문제를 발견하면 보고만 하고 수정하지 않는다. 
---

## 기능 구현 착수 규칙
> 기능 구현을 요청받으면 바로 작업하지 않고 아래 형식으로 먼저 **브리핑**한 뒤 **승인**을 받고 착수한다.

```
## 구현 브리핑: [기능명]

**작업 범위**
(구현 내용 요약)

**생성 / 수정 파일**
- 생성: 파일 경로(역할)
- 수정: 파일 경로(변경 내용)

**작업 순서** ('4. 검증 가능한 목표'의 포맷)
1. 단계 1
2. 단계 2

이대로 진행하시겠습니까?
```

- 문서와 오타 등 코드가 아닌 단순 수정에 대해서는 브리핑하지 않는다. 
---

## 응답 규칙
- 소스 코드의 주석은 한국어로 작성한다.
- 변수, 함수, 클래스 이름은 영어로 쓴다. 참고 자료로 (\Docs\SourceCode) 참조.
- 불필요한 코드, 쓰지 않는 변수, 빈 메서드는 만들지 않는다.
