**목표:** 이후 전 단계가 기대는 기반 확정. 스키마와 좌표 규칙을 대충 잡으면 전부 재작업이 되므로, 속도보다 설계에 시간을 쓴다.

**관련 ID:** F-01

### 체크리스트

#### 프로젝트 세팅
- [ ] Unity 6 (6000.3.9f1 LTS)로 프로젝트 생성
- [ ] Git 저장소 초기화, Unity용 `.gitignore` 적용, 첫 커밋
- [ ] 폴더 구조 생성 (Scripts / Data / Prefabs / Scenes / Art 등)
- [ ] 패키지·렌더 파이프라인 이상 없이 열리는지 확인 (환경 이슈가 나면 하루를 소모할 수 있으니 오전 중 확인)

#### 결정 사항 확정
- [ ] **JSON vs CSV** 택 1 → 결정 후 문서에 기록
- [ ] **3D 쿼터뷰 vs 2D** 확정 (마우스 좌표 변환 방식이 갈림)
- [ ] **좌표계 규칙:** 칸은 XZ 평면, 칸 거리 = 상하좌우 칸 수, 칸 인덱스 ↔ 월드 좌표 변환 규칙

#### 데이터 스키마 설계
- [ ] **유닛:** 이름, HP, EN, 이동력, 무기 목록
- [ ] **무기:** 이름, 공격력, 최소·최대 사거리, 범위 모양, EN 소모량
  - 범위 모양을 확장 가능한 필드로 설계 (F-24 범위 무기 3종 이상을 데이터 추가만으로 대응)
- [ ] **맵:** 가로·세로 크기, 칸별 지형 ID, 지형 정의 (이동 비용, 진입 가능 여부), 유닛 초기 배치
  - 스테이지 2개 이상, 10×10 이상을 담을 수 있는 구조인지 확인
- [ ] 스키마를 문서로 남김 (내일 샘플 JSON 작성의 기준)

### 오늘 하지 않는 것
- 샘플 JSON 실제 작성, 지형 3종 정의, 전투 계산식 초안 → 11/07
- 맵 로더, 그리드 생성, 마우스 강조 → 11/08

### 완료 기준
- [ ] 빈 프로젝트가 Git에 올라가 있고 정상적으로 열린다
- [ ] JSON/CSV, 2D/3D, 좌표계가 문서에 확정되어 있다
- [ ] 유닛·무기·맵 스키마가 문서화되어 있다

### 리스크
- 스키마를 대충 잡으면 이후 전 단계에서 재작업 발생
- JSON vs CSV 결정이 늦어지면 로더 작업 지연
- Git/패키지 환경 이슈 시 하루 소모 가능
