# 데일리 체크 규칙
> 개발 일정이 계획대로 가고 있는지 매일 점검하기 위한 규칙.
>
> 데일리 체크 양식은 `Docs\Template\DailyCheckTemplate.md`를 참고.
>
> 해당 문서는 데일리 체크의 작성 시점, 기록 방식, 이월·동결 판단 기준을 정의한다.
---

## 개요
- 데일리 체크는 `Docs\ProjectPlan.md`의 `3. 개발 스케줄`을 하루 단위 체크리스트로 옮긴 문서이다.
- 일정과 Feature ID의 원본은 `ProjectPlan.md`이다. 데일리 체크는 **진행 기록**만 담당하며, 일정 자체를 바꿀 때는 `ProjectPlan.md`를 먼저 고친다.

---

## 1. 파일 위치와 구성
- 파일은 `Docs\DailyCheck\DailyCheck.md` **하나**에 누적하여 작성한다.
- 구성 순서는 다음과 같다.
  1. 프로젝트 요약 (레퍼런스, 엔진, 기간)
  2. `0. 사용법`: 이 규칙 문서 경로만 적는다. 규칙을 복사하지 않는다.
  3. `1. 전체 진행 현황` 표와 `마일스톤` 표
  4. 단계(P0, P1, P2)별 `Day N` 섹션
  5. 부록 (리스크 요약, 필수 / 선택 / 제외 구현 ID 목록)
- 프로젝트 시작일(1일차)에 모든 `Day N` 섹션을 양식대로 미리 만들어 둔다.

---

## 2. Day 섹션 작성 규칙
### 제목
- 형식: `## Day N – MM/DD(요일) · 강도`
- 강도는 `풀`(종일 작업) 또는 `라이트`(가벼운 작업 위주) 중 하나를 쓴다.
- 특별한 날은 제목 끝에 표시를 붙인다.

| 표시 | 언제 쓰나 |
|:---:|:---:|
| ⚠️ | 해당 단계에서 가장 무거운 날, 대응 여유가 그날뿐인 날 |
| 🔄 | 이월분을 흡수하는 완충 구간 |
| 🧊 | 기능 동결일 |

### 섹션별 규칙
| 섹션 | 필수 여부 | 작성 규칙 |
|:---:|:---:|---|
| 목표 | 필수 | 한두 문장. 그날 무엇이 되어 있어야 하는지를 적는다. 마일스톤 달성일이면 함께 적는다. |
| 관련 ID | 필수 | `ProjectPlan.md`의 Feature ID (`F-01` 등). 없으면 `-` |
| 체크리스트 | 필수 | 한 항목은 확인 가능한 작업 하나. 항목이 많으면 `####` 소제목으로 묶는다. |
| 오늘 하지 않는 것 | 선택 | 헷갈리기 쉬운 다음 날 작업이 있을 때만 적고, 넘어갈 날짜를 함께 적는다. |
| 밀릴 경우 대응 | 선택 | 무거운 날에만 적는다. 무엇을 후순위로 뺄 수 있는지 적는다. |
| 완료 기준 | 필수 | 체크리스트를 다 하지 못해도 이것만 되면 그날은 완료로 본다. 2~3개 이내 |
| 리스크 | 필수 | `ProjectPlan.md`의 `비고 (밀릴 수 있는 사항)`을 옮긴다. |
| 마무리 점검 | 필수 | 아래 `3. 마무리 점검` 규칙을 따른다. |

---

## 3. 하루 진행 방식
### 아침 (작업 시작 전)
- 오늘의 `Day N` 섹션과 전날 `마무리 점검`의 `밀린 것`을 확인한다.
- 이월된 항목이 있으면 오늘 체크리스트 맨 위에 `(이월)`을 붙여 추가한다.

### 작업 중
- 완료한 항목은 `[ ]` → `[x]`로 바꾼다.
- 직접 확인하지 못한 항목은 체크하지 않는다. (예: 유니티 에디터에서 실행해 보지 않은 기능)

### 저녁 (작업 종료 후)
- `마무리 점검` 표를 모두 채운다. 쓸 내용이 없는 칸은 `없음`으로 적는다. 빈칸으로 두지 않는다.
- `1. 전체 진행 현황` 표의 `완료` 칸은 그날의 `완료 기준`을 모두 충족했을 때만 `[x]`로 바꾼다.

---

## 4. 이월 규칙
- 끝내지 못한 항목은 `마무리 점검`의 `밀린 것` 칸에 적고, **다음 날** 체크리스트로 옮긴다.
- 같은 항목이 **2일 연속** 이월되면 범위를 줄여 최소 구현으로 마감한다. 줄인 내용은 `막힌 점 / 결정 보류 사항` 칸에 적는다.
- 완충 구간(🔄)에서는 새 작업보다 이월분을 먼저 처리한다.

---

## 5. 기능 동결과 마일스톤
- 기능 동결일(🧊) 이후에는 **신규 기능을 추가하지 않는다.** 버그 수정, 리팩토링, 폴리싱, 선택 구현만 진행한다.
- 동결일까지 끝나지 않은 필수 기능은 최소 구현으로 마감한다.
- 선택 구현은 필수 기능이 안정화된 경우에만 `ProjectPlan.md`의 우선순위 순서대로 착수한다.
- `마일스톤` 표의 `달성` 칸은 마일스톤 문장에 적힌 동작을 실제로 확인했을 때만 `[x]`로 바꾼다.

---

## 6. 워크 플로우 연계
- 개발·버그수정 요청을 받으면, 해당 작업이 오늘 `Day N` 체크리스트의 어느 항목인지 확인한다.
  - 오늘 일정에 없는 작업이면 사용자에게 알리고 진행 여부를 묻는다.
- 이슈 작성 시 `관련 ID`를 이슈 제목 또는 `배경 및 목적`에 반영한다.
- `4. 사용자 검수`에서 승인된 작업은 데일리 체크의 해당 항목을 `[x]`로 바꾸도록 사용자에게 권유한다.
- 데일리 체크 파일의 수정 역시 사용자의 승인 후 진행한다.
