# Github Pull Request 등록
> 이 스킬은 절차와 멘트 규격만 정의한다.
>
> PR의 작성 규칙과 양식은 아래 원본 문서를 따르며, 이 스킬에 규칙을 복사하지 않는다.

---

## 참조 문서
| 문서 | 읽을 섹션 | 용도 |
|:---:|:---:|:---:|
| `Docs\Documentation\WorkFlowRules.md` | `6. Commit / Push`, `7. PR` | PR 진입 조건, 등록 후 진행 조건 |
| `Docs\Documentation\GitHub Pull Request Rule.md` | 상단 개요, `운영 방식`, `PR 만들기`, `제목` | base/compare 방향, 리뷰어, 제목 말머리 규칙 |
| `Docs\Template\PullRequestTemplate.md` | 전체 | PR 본문 양식 |

## 절차
1. **문서 확인**: PR 작성 명령을 받으면 위 참조 문서의 해당 섹션을 읽는다.
2. **사전 점검**: 아래 항목을 확인한다. 하나라도 충족하지 않으면 `멘트 규격 ① 사전 점검 실패`로 알리고 종료한다.
   - 현재 브랜치가 `main`, `main-develop`이 아니다.
   - 작업 브랜치가 원격에 Push되어 있고, 로컬에 Push되지 않은 커밋이 없다. (Push는 사용자가 직접 수행하며, Claude는 대신 Push하지 않는다.)
   - 같은 브랜치로 열려 있는 PR이 없다.
3. **정보 수집**: 연결할 이슈 번호를 사용자에게 확인하고, 해당 이슈의 `작업 내용`과 `완료조건 (DoD)`를 읽는다. `main-develop` 대비 커밋 목록과 변경 파일을 확인한다.
4. **초안 작성**: `PullRequestTemplate.md` 양식에 맞춰 본문을 작성한다.
   - 이슈의 `완료조건 (DoD)`는 PR 본문의 `완료조건 (DoD)` 섹션에 반영한다.
   - 직접 확인하지 못한 DoD 항목은 체크하지 않는다.
5. **승인 요청**: `멘트 규격 ② 승인 요청`으로 사용자 승인을 받는다. 수정 요청이 있으면 반영 후 다시 승인을 받는다.
6. **등록**: 승인 후 `gh pr create`로 등록한다. base·compare 방향과 리뷰어는 `GitHub Pull Request Rule.md`를 따른다.
7. **결과 보고**: `멘트 규격 ③ 등록 완료`로 알린다. 이후 단계는 `WorkFlowRules.md`의 `8. 병합, 브랜치 파기`를 따르며, Claude는 병합하지 않는다.

## 멘트 규격
> 각 멘트는 아래 형식을 지키고, 항목마다 한 줄로 간결하게 작성한다.

### ① 사전 점검 실패
```
⛔ PR 등록 불가
- 사유: (충족하지 못한 점검 항목 한 줄)
- 필요한 조치: (사용자가 직접 수행할 작업 한 줄)
조치 후 다시 요청해 주세요. (`/github-pr`)
```

### ② 승인 요청
```
## PR 등록 확인
- 방향: main-develop ← (작업 브랜치)
- 제목: [말머리] PR 내용
- 리뷰어: (지정 리뷰어)
- 연결 이슈: #번호 (없으면 "없음")
- 커밋 / 변경 파일: N개 / N개
- DoD: N개 항목 반영 (미검증 N개)

(PR 본문 전체 미리보기)

이대로 등록하시겠습니까?
```

### ③ 등록 완료
```
✅ PR 등록 완료
- PR: #번호 (링크)
- 리뷰어: (지정 리뷰어)
병합은 리뷰어 승인 후 진행됩니다.
```
