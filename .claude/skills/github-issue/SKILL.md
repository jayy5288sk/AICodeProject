# Github Issue 등록
> 이 스킬은 절차와 멘트 규격만 정의한다.
>
> 이슈의 작성 규칙과 양식은 아래 원본 문서를 따르며, 이 스킬에 규칙을 복사하지 않는다.

---

## 참조 문서
| 문서 | 읽을 섹션 | 용도 |
|:---:|:---:|:---:|
| `Docs\Documentation\WorkFlowRules.md` | `0. 업무 유형 판별`, `1. Github Issue` | 이슈 등록 대상 여부, 등록 후 진행 조건 |
| `Docs\Documentation\GitHub Issue Rule.md` | 전체 | 섹션별 작성 규칙, 제목 및 Label 규칙 |
| `Docs\Template\IssueTemplate.md` | 전체 | 이슈 본문 양식 |

---

## 절차
1. **대상 확인**: `WorkFlowRules.md`의 기준으로 업무 유형을 판별한다. 이슈 등록 대상이 아니면 그 사유를 알리고 종료한다.
2. **권유**: 사용자가 이슈 작성을 명령하지 않은 상태라면, `멘트 규격 ① 권유`로 권유만 하고 명령을 기다린다.
3. **문서 확인**: 이슈 작성 명령을 받으면 위 참조 문서의 해당 섹션을 읽는다.
4. **정보 수집**: `GitHub Issue Rule.md`에서 사용자에게 질문하도록 정한 항목을 질문한다. 답을 받지 못하면 이슈를 작성하지 않는다.
   - 구현 방향(구상)을 질문할 때는 `멘트 규격 ② 구현 방향 질문`으로 선택지에 번호를 붙여 제시하고, 사용자가 번호로 답할 수 있게 한다.
   - 선택지는 정답을 정하지 않고 각 방향의 특징만 적는다. 사용자가 번호 대신 직접 서술한 답도 받는다.
5. **승인 요청**: 양식에 맞춰 초안을 작성하고, `멘트 규격 ③ 승인 요청`으로 사용자 승인을 받는다.
6. **등록**: 승인 후 `gh issue create`로 등록한다. 필요한 Label이 없으면 `GitHub Issue Rule.md`에 따라 Label을 먼저 만든다.
7. **결과 보고**: 등록된 이슈 번호와 링크를 알린다. 이후 단계는 `WorkFlowRules.md`의 `1. Github Issue` 조건을 따른다.

## 멘트 규격
> 각 멘트는 아래 형식을 지키고, 항목마다 한 줄로 간결하게 작성한다.

### ① 권유
```
📌 이슈 등록 권유
- 유형: [개발 / 버그수정]
- 제목(안): [Label] 제목
- 사유: (한 줄)
이슈를 등록할까요? (`/github-issue`)
```

### ② 구현 방향 질문
```
🧭 구현 방향 선택
Q. (질문 한 줄)
1. (방향 A) — (특징 한 줄)
2. (방향 B) — (특징 한 줄)
3. (방향 C) — (특징 한 줄)
0. 직접 입력
번호로 답해 주세요. (여러 개 선택 시 쉼표로 구분: 1,3)
```

### ③ 승인 요청
```
## 이슈 등록 확인
- 제목: [Label] 제목
- Label: [Label]  (미등록 시 "신규 생성 예정" 표기)
- 배경 및 목적: (사용자 답변 요약)
- 목표 / 작업 내용 / DoD: 각 N개 항목

(이슈 본문 전체 미리보기)

이대로 등록하시겠습니까?
```
